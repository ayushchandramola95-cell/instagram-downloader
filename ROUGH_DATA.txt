# **InstaSnap (GramSave) - Instagram Video Downloader Project Overview**

### **Backend (API Routes)**

Located in `src/app/api/`:

#### **1. `/api/fetch-media` (POST)**
**Purpose**: Extract Instagram media metadata and download URLs

**Flow**:
1. Validates Instagram URL via `validateInstagramUrl()`
2. Applies rate limiting (30 requests/min per IP by default)
3. Optionally verifies Cloudflare Turnstile anti-bot token
4. Calls `extractInstagramMedia()` from `instagram-extractor.ts`
5. Returns JSON with media details, resolutions, thumbnails

**Key Features**:
- Multi-tier extraction with automatic failover
- Supports Reels, Posts, Stories, Carousels, Profile DPs
- Returns structured `ExtractedMedia` object

---

#### **2. `/api/download` (GET)**
**Purpose**: Stream media files with proper download headers (bypasses Instagram CORS/hotlinking)

**Flow**:
1. Validates download target URL is authentic Instagram CDN via `validateDownloadTargetUrl()`
2. Applies rate limiting (60 downloads/min per IP)
3. Records download analytics
4. For audio/trimmed videos: Uses **FFmpeg on-the-fly processing**
5. For standard videos/photos: Proxies stream directly from CDN

**Query Parameters**:
- `url`: Encoded CDN URL
- `filename`: Sanitized output filename
- `audioUrl`: (Optional) Separate audio stream for DASH video muxing
- `start`: (Optional) Trim start time in seconds
- `duration`: (Optional) Clip duration for trimming

**Key Features**:
- Real-time FFmpeg transcoding for trimmed clips and audio extraction
- SSRF protection with CDN whitelist
- Sets `Content-Disposition: attachment` to force browser download
- Supports video+audio muxing for DASH formats

---

#### **3. `/api/analytics` (POST)**
**Purpose**: Track download events (optional analytics store)
- Records download counts by media type
- Stores in `src/data/analytics.json`

#### **4. `/api/translations` (GET)**
**Purpose**: Serve internationalization strings
- Returns translations from `src/data/translations.json`

### **Core Business Logic** (`src/lib/`)

#### **`instagram-extractor.ts`** 
**The heart of the extraction system** - implements a **5-tier failover strategy**:

1. **yt-dlp** (Primary) - Self-hosted CLI extraction
2. **Direct Instagram Mobile API** - Authenticated Instagram API calls with cookies
3. **RapidAPI** (Optional) - Third-party API fallback if key is configured
4. **GraphQL Query** - Fallback Instagram web GraphQL endpoint
5. **Embed Scraping** - Public embed page extraction as last resort

**Special Handlers**:
- `extractUserStories()`: Fetches active 24-hour stories for a username
- `extractInstagramProfile()`: Extracts HD profile pictures
- `extractViaDirectApi()`: Parses carousel albums, video formats, and photos
- `shortcodeToMediaId()`: Converts Instagram shortcodes to numeric media IDs

---

#### **`ytdlp-extractor.ts`**
**yt-dlp CLI Integration**:
- Executes `yt-dlp` with secure `child_process.execFile`
- Auto-detects and uses `cookies.txt` for authentication
- Supports proxy configuration via environment variables
- Parses JSON output and maps to structured `ExtractedMedia` format
- Handles multi-item carousels and DASH video/audio streams

**Key Functions**:
- `extractWithYtDlp()`: Main extraction wrapper
- `buildResolutionsFromOutput()`: Constructs quality options from yt-dlp formats

- `validateInstagramUrl()`: Strict URL validation with SSRF protection

## **🚀 Key Workflows**

### **User Downloads a Video**:
1. User pastes Instagram URL into input
2. Frontend calls `POST /api/fetch-media`
3. Backend validates URL, checks rate limit
4. Calls extraction pipeline (yt-dlp → Direct API → fallbacks)
5. Returns media metadata with multiple quality options
6. User selects quality and clicks download
7. Frontend triggers `GET /api/download?url=...`
8. Backend streams file with `Content-Disposition: attachment`
9. Browser saves file to user's device

### **Carousel Album Download**:
1. Extraction detects multi-slide post
2. Returns `carouselItems[]` array
3. User can:
   - Download slides individually
   - Batch download all slides sequentially
   - Bundle all slides into a single ZIP archive (client-side with JSZip)

### **Audio Extraction**:
1. User selects "Audio MP3" quality option
2. Frontend passes audio stream URL to `/api/download`
3. FFmpeg extracts audio track: `ffmpeg -i video.mp4 -vn -c:a libmp3lame -b:a 320k output.mp3`
4. Streams MP3 directly to browser

### **Video Trimming**:
1. User sets start time and duration in UI
2. Frontend adds `&start=15&duration=30` to download URL
3. FFmpeg trims video on-the-fly: `ffmpeg -ss 15 -t 30 -i video.mp4 -c copy output.mp4`
4. Streams trimmed clip
